# Toepen API (Plan 1 of 3) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A plain-PHP JSON API with MySQL that handles accounts, groups, players, games, sync requests and admin functions for the Toepen PWA and the Android upload.

**Architecture:** One front controller (`api/index.php`) builds a `Request`, passes it to `App::handle()`, which routes to handler functions and returns a `Response`. Handlers take a `Ctx` (PDO + authenticated user). Tests call `App::handle()` in-process against a real MySQL 8.4 test database in Docker, so no HTTP server is needed for tests.

**Tech Stack:** PHP 8.4, PDO MySQL, MySQL 8.4, PHPUnit 11 (dev only, via Composer in Docker), Docker Desktop (local only).

**Spec:** `docs/superpowers/specs/2026-11-18-toepen-pwa-design.md`

**Plans in this series:** 1 API (this) → 2 PWA (`2026-11-18-toepen-2-pwa.md`) → 3 Android upload (`2026-11-18-toepen-3-android.md`). Plans 2 and 3 depend on the **API contract** section below.

## Global Constraints

- Production: netcup web hosting, PHP 8.4.27, MySQL 8.4.13, `https://toepen.t-wezeman.nl`, API under `/api/`.
- Plain `.php` files on the server: no framework, no Composer autoload on the server, no runtime dependencies. Composer/PHPUnit exist only in the local Docker setup.
- The owner uploads files manually. No deploy automation.
- `api/config.php` is never committed and never part of the upload folder; `api/config.example.php` is.
- All responses are JSON. Errors: `{ "error": "<code>", "message": "<Dutch text>" }`. Internal details go to `error_log()`, never into the response.
- Table names must avoid MySQL reserved words: the groups table is `game_groups`.
- All text columns `utf8mb4` / `utf8mb4_0900_ai_ci` (case- and accent-insensitive), so `UNIQUE(group_id, name)` on players is case-insensitive.
- Dutch user-facing messages, matching the Android app's tone.

## Review Focus

1. **Apache/PHP-FPM strips the `Authorization` header** on many Plesk setups → every request looks logged out. `.htaccess` must pass it through, and the API must also accept `X-Auth-Token`. Test: `test_token_accepted_via_x_auth_token_header` (Task 2).
2. **Re-uploading the same game with different content** (e.g. a retried upload after a client bug) must not overwrite or duplicate: same UUID → 200 `duplicate: true`, stored data unchanged. Test: `test_duplicate_upload_with_different_body_keeps_original` (Task 5).
3. **A player name that was merged away** arriving in a later upload must land on the merge target, also when the chain is two deep. Test: `test_upload_follows_merge_chain` (Task 5).
4. **Approving the same sync request twice** (double tap, two admin tabs) must not import games twice or create two groups. Test: `test_approve_twice_returns_conflict` (Task 7).
5. **A disabled user's existing token** must stop working immediately, not just block new logins. Test: `test_disabled_user_token_rejected` (Task 2).

## API contract

Base URL: `https://toepen.t-wezeman.nl/api`. Auth: `Authorization: Bearer <token>` or `X-Auth-Token: <token>`. Timestamps: ISO 8601 with offset, e.g. `2026-11-18T21:04:05+01:00`. JSON bodies, `Content-Type: application/json`.

### Shapes

```
User        { id:int, username:string, is_admin:bool }
Player      { id:int, name:string, games_played:int }
GamePlayer  { name:string, final_score:int, boer_count:int }          // array order = seat order
Game        { id:uuid, group_id:int, recorded_by:string, started_at:string,
              duration_ms:int, max_penalty_points:int, ended_early:bool,
              winner:string|null, players:GamePlayer[] }
Group       { id:int, name:string, creator:string, max_penalty_points:int,
              players:Player[], games:Game[] }                         // games: non-deleted, newest first
GameUpload  = Game without recorded_by (group_id omitted inside sync requests)
SyncRequest { id:int, group_name:string, source:"pwa"|"android",
              status:"pending"|"approved"|"rejected",
              resolved_group_id:int|null, reject_reason:string|null, created_at:string }
```

### Validation of a GameUpload (code `validation_failed`, 422)

- `id` is a UUID string (36 chars, 8-4-4-4-12 hex).
- 2–8 players; names non-empty after trim, ≤ 40 chars, unique case-insensitively within the game.
- `max_penalty_points` 1–100; each `final_score` 0..max_penalty_points; `boer_count` ≥ 0; `duration_ms` ≥ 0.
- `winner` is null or equals (case-insensitively) one of the player names.
- `ended_early` true ⇒ `winner` null.
- `started_at` parses as ISO 8601.

### Endpoints

| Method + path | Body | Success | Errors |
|---|---|---|---|
| `POST /login` | `{username, password, device_name}` | 200 `{token, user:User}` | 401 `invalid_credentials`, 429 `too_many_attempts` |
| `POST /logout` | – | 204 | 401 |
| `GET /me` | – | 200 `{user:User}` | 401 |
| `GET /groups` | – | 200 `{groups:Group[]}` + `ETag`; 304 if `If-None-Match` matches | 401 |
| `PATCH /groups/{id}` | `{max_penalty_points}` | 200 `{group:Group}` | 403 `not_member`, 404, 422 |
| `POST /players` | `{group_id, name}` | 201 `{player:Player}` | 403, 404, 409 `name_taken` `{player:Player}`, 422 |
| `POST /games` | `GameUpload` | 201 `{game:Game}`; 200 `{game:Game, duplicate:true}` | 403 `not_member`, 404 `group_not_found`, 422 |
| `DELETE /games/{id}` | – | 204 | 403 `not_allowed`, 404 |
| `POST /sync-requests` | `{source, group_name, games:GameUpload[]}` | 201 `{request:SyncRequest}` | 422 |
| `GET /sync-requests/mine` | – | 200 `{requests:SyncRequest[]}` | 401 |
| `GET /admin/users` | – | 200 `{users:(User & {disabled:bool, last_used_at:string|null})[]}` | 403 `admin_only` |
| `POST /admin/users` | `{username, password, is_admin}` | 201 `{user}` | 409 `username_taken`, 422 |
| `PATCH /admin/users/{id}` | any of `{password, disabled, is_admin}` | 200 `{user}` | 404, 422 |
| `POST /admin/users/{id}/revoke-tokens` | – | 204 | 404 |
| `GET /admin/groups` | – | 200 `{groups:{id,name,creator,members:User[],game_count}[]}` | 403 |
| `POST /admin/groups/{id}/members` | `{user_id}` | 204 (idempotent) | 404 |
| `DELETE /admin/groups/{id}/members/{user_id}` | – | 204 | 404 |
| `POST /admin/groups/merge` | `{source_group_id, target_group_id}` | 200 `{group:Group}` | 404, 422 (same id) |
| `POST /admin/players/merge` | `{source_player_id, target_player_id}` | 204 | 404, 422 (different groups / same id) |
| `GET /admin/sync-requests` | – | 200 `{requests:(SyncRequest & {requested_by:string, game_count:int, player_names:string[]})[]}` (pending first) | 403 |
| `GET /admin/sync-requests/{id}/matching?group_id=N` | – | 200 `{matches:{name, match:"exact"|"similar"|"new", player_id:int|null, suggestions:Player[]}[]}` | 404 |
| `POST /admin/sync-requests/{id}/approve` | `{mode:"new"}` or `{mode:"link", group_id, mapping:{[name]:player_id|null}}` | 200 `{request:SyncRequest}` | 404, 409 `already_resolved`, 422 |
| `POST /admin/sync-requests/{id}/reject` | `{reason}` | 200 `{request}` | 404, 409 |
| `GET /admin/games/deleted` | – | 200 `{games:(Game & {deleted_at, deleted_by})[]}` | 403 |
| `POST /admin/games/{id}/restore` | – | 204 | 404 |
| `POST /admin/groups/{id}/delete-games` | `{short_only:bool}` | 200 `{deleted:int}` (short = `duration_ms < 60000`) | 404 |
| `GET /admin/export` | – | 200 full dump `{users, groups, players, games, sync_requests}` (no hashes) | 403 |

Login rate limit: 5 failed attempts per username within 15 minutes → 429 until the window passes. A disabled user gets 401 `invalid_credentials` on login and 401 on every token use.

### Similar-name rule (shared with the PWA, must match exactly)

Normalise: trim, lowercase, collapse whitespace. Two different normalised names `a`, `b` are **similar** when either:
- the shorter has ≥ 3 chars and the longer starts with it (`rav` / `ravi`, `ravi` / `ravi b`), or
- Levenshtein(a, b) ≤ 1 when the longer has ≤ 5 chars, ≤ 2 otherwise.

Equal normalised names are an **exact** match, not similar.
