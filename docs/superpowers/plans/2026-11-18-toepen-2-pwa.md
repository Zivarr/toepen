# Toepen PWA (Plan 2 of 3) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An installable, offline-first PWA for Toepen (iPhone + Android) with local and server-synced groups, the full game, statistics and admin screens.

**Architecture:** Pure TypeScript core modules (game engine, stats, name matching) with no UI or storage dependencies; a Dexie (IndexedDB) store; an API client plus outbox/refresh sync modules; Preact screens on a hash router. Everything renders from IndexedDB first and syncs in the background.

**Tech Stack:** Vite 6, TypeScript 5, Preact 10, Dexie 4, vite-plugin-pwa (Workbox), canvas-confetti, Vitest + fake-indexeddb, Playwright (WebKit).

**Spec:** `docs/superpowers/specs/2026-11-18-toepen-pwa-design.md`
**Depends on:** Plan 1 (`2026-11-18-toepen-1-api.md`) — its **API contract** section defines every request/response shape and the **similar-name rule** used here.

## Global Constraints

- Hosted at `https://toepen.t-wezeman.nl/` (PWA at root, API at `/api/`). Vite `base: '/'`. Dev server proxies `/api` → `http://localhost:8080`.
- Hash routing (`#/…`) so the static host needs no rewrite rules.
- All UI text in Dutch, same wording as the Android app where it exists (e.g. "Deel resultaten", "Strafpunt toevoegen aan %s?", "Revanche").
- Theme colours from Android: primary `#1B5E20`, dark `#003300`, accent `#2E7D32`, remove `#EF5350`.
- Login required for every screen except `#/login`.
- Max 8 players, min 2 per game (as Android).
- Must work as an installed home-screen app on iOS Safari 16.4+ and Android Chrome.
- The service worker never reloads the page by itself; updates only on the user's tap, and the update banner is hidden on the game screen.
- `npm` scripts: `dev`, `build`, `test` (Vitest), `e2e` (Playwright).

## Review Focus

1. **Background refresh wiping unsent games:** a refresh from the server must not remove games that are still in the outbox from the cached group, or they vanish from the leaderboard until upload. Test: `refresh keeps outbox games in the cached group` (Task 6).
2. **iOS kills the app mid-game:** reopening must resume exactly, including undo history and round points. Test: `current game round-trips through storage with history` (Task 4) and e2e `resume after reload` (Task 12).
3. **Upload fails permanently (removed from group):** the game must stay visible and exportable, not silently retried forever or lost. Test: `403 marks outbox item failed and stops retrying` (Task 6).
4. **Two outbox flushes at once** (app foreground + online event fire together) must not double-post or corrupt state. Test: `concurrent flush calls share one run` (Task 6).
5. **Token revoked while offline games are queued:** after re-login the queue must still upload. Test: `401 keeps outbox and triggers login, later flush succeeds` (Task 6).

**Files:**
- Create: `pwa/src/game/engine.ts`, `pwa/src/game/tally.ts`, `pwa/tests/unit/engine.test.ts`, `pwa/tests/unit/tally.test.ts`

**Interfaces:**
- Produces:

```ts
interface GameState {
  players: string[]; maxPenaltyPoints: number; startedAt: number;     // epoch ms
  scores: Record<string, number>; boer: Record<string, number>;
  roundPoints: number;
  history: { scores: Record<string, number>; boer: Record<string, number> }[];
  isOver: boolean; endedEarly: boolean; winner: string | null; durationMs: number;
}
type Action = { type: 'klop' } | { type: 'penalty' | 'fold' | 'boer'; name: string }
            | { type: 'undo' } | { type: 'nextRound' } | { type: 'endEarly' };
type GameEvent = { type: 'eliminated'; name: string } | { type: 'gameOver'; winner: string | null }
               | { type: 'undoEmpty' };
function newGame(players: string[], maxPenaltyPoints: number, now: number): GameState;
function apply(s: GameState, a: Action, now: number): { state: GameState; events: GameEvent[] };
function isEliminated(s: GameState, name: string): boolean;
function toUpload(s: GameState, id: string, groupId: number): GameUpload;   // started_at ISO with local offset
function tally(score: number): string;   // 0 → "0"; 7 → "卌 ||"; 10 → "卌 卌"
```

Rules (spec §4): penalty adds `roundPoints` capped at max; fold adds `roundPoints − 1` capped; boer −1 (min 0) and boer +1; undo restores the previous `{scores, boer}` snapshot (boer is restored too — this deliberately fixes the Android app, which leaves the boer count after undo); nextRound resets `roundPoints` to 1 and clears history; actions on an eliminated player and all actions after `isOver` are ignored (no events); game over when ≤ 1 player below max: `winner` = remaining player or `null` ("Niemand"); `endEarly` sets `isOver`, `endedEarly`, `winner: null`. `durationMs` = `now − startedAt` at game over.

- Produces:

```ts
flushOutbox(): Promise<{ sent: number; failed: number; pending: number }>;   // single-flight
refresh(): Promise<'updated' | 'unchanged' | 'offline'>;
requestSync(key: GroupKey): Promise<void>;           // POST sync-request with all local games; sets syncStatus 'pending'
checkSyncRequests(): Promise<void>;                  // approved → completeApproval; rejected → syncStatus 'rejected' + reason
completeApproval(localKey: GroupKey, serverId: number): Promise<void>;
      // re-key games to server:<id>, enqueue each in outbox with group_id = serverId, delete local group, then flush + refresh

```

Outbox result handling (spec §8.3): success/duplicate → delete item; `NetworkError` or status ≥ 500 → keep pending, stop this run; 403/404/422 → `status: 'failed'`, `reason` = API message, continue with next. 401 → stop, keep pending.
Refresh: replace server-kind groups and their games with server data, then re-add every outbox game (pending or failed) for those groups; keep `pendingPlayers` not yet present on the server; remove server groups no longer returned (user was removed) but keep their failed outbox items.
